# 首页成交驾驶舱设计方案（V1）

## 文档信息

- 产品：AI员工一体机销售演示系统
- 页面：首页
- 方案版本：V1
- 文档状态：待产品经理确认
- 方案类型：产品设计方案
- 本文范围：仅讨论首页成交驾驶舱，不涉及代码、页面修改或开发实现

## 一、设计目标

首页不是普通后台首页，也不是数据报表首页，而是销售人员见客户时的第一张“价值证明页”。它需要让企业老板在短时间内理解三件事：

1. 这是一名持续工作的AI数字员工，而不是单一软件工具。
2. AI正在围绕内容、获客、接待和跟进持续工作。
3. 销售现在可以立即进入一套完整的客户演示流程。

### 目标体验

- 10秒内看懂产品定位和当前运行状态。
- 30秒内看懂AI如何从内容生产走到客户跟进。
- 1次点击进入客户演示，不需要先阅读复杂数据。
- 页面第一眼展示“获客与成交相关信号”，技术细节放到后续页面。
- 保持深色企业级AI硬件控制中心气质，避免变成普通ERP或白底卡片墙。

## 二、首页布局

保留现有桌面软件的左侧导航、顶部状态栏和深色视觉体系。首页内容区调整为“上方价值判断、中央工作状态、下方行动路径”的结构。

### 1. 顶部价值区

顶部只保留一个主标题、一个副标题和一个主要行动入口。

建议表达：

- 主标题：`AI员工正在持续工作`
- 副标题：`让AI接管重复运营工作，让销售专注客户与成交。`
- 辅助状态：当前企业、AI员工在线、演示模式
- 主按钮：`开始客户演示`

主标题不再同时承担产品介绍、功能解释和数据说明。产品设备和AI员工状态由中央视觉区承担，顶部只负责建立判断。

### 2. 中央主视觉区

中央区域由两个主要面板组成，左右比例建议约为 40% : 60%。

#### 左侧：AI员工工作状态

展示黑色服务器机箱款AI员工一体机、AI机器人和本地运行状态。

画面重点：

- 设备是主角，保持金属外壳、运行指示灯、局部反射和接触阴影。
- 机器人是辅助角色，体现“AI员工”而不是装饰插画。
- 显示`AI员工在线`、`本地系统运行正常`等状态信息。
- 设备旁保留少量产品价值说明，例如本地化部署、企业专属知识库。
- 不在设备面板内堆叠功能列表、服务清单和技术参数。

#### 右侧：今日获客与成交信号

右侧不采用六张等权指标卡，而采用一个统一的“今日工作结果”区域。核心是让老板先看到销售价值，再看到运营过程。

建议第一层突出三个数字：

- 新增客户线索：8
- AI接待次数：23
- 待跟进客户：12

三个数字都必须标注`演示数据`，并配合状态短语：

- 新增客户线索：等待销售确认
- AI接待次数：知识库响应
- 待跟进客户：需要及时处理

建议第二层以一条简洁路径说明数据如何产生：

`内容产出 → 平台发布 → 客户互动 → AI接待 → 销售跟进`

内容生成量、发布量和GEO关键词进度作为运营支撑信息放在第二层或折叠区域，不与客户线索、接待和跟进抢夺视觉焦点。

### 3. 下方工作流区

保留现有工作流表达，但将其定位为“AI如何工作”的证据，不作为页面主标题区。

建议节点：

`企业知识库 → AI内容生成 → 多平台发布 → 客户产生互动 → AI接待 → 销售跟进`

最后的`成交`不建议在没有真实成交数据时作为已完成状态展示。可以表达为`进入成交环节`或`待人工推进`，避免让演示数据被理解为成交承诺。

### 4. 下方行动区

行动区只保留三种层级：

1. 主行动：`开始客户演示`
2. 次行动：`配置当前企业`
3. 辅助行动：`查看今日任务`

主行动应当在顶部或中央主视觉区出现一次即可。页面下方不再重复放置同名主按钮，避免销售不知道应该点击哪个入口。

## 三、信息层级

### P0：老板第一眼必须看到

- 这是AI员工一体机。
- AI员工当前在线并持续工作。
- 当前演示企业是谁。
- 新增客户线索、AI接待、待跟进这三个销售相关信号。
- `开始客户演示`入口。

### P1：用于建立可信度

- 内容生产到销售跟进的完整工作流。
- 多平台运营正在运行。
- AI接待基于企业资料响应客户。
- 数据是本地演示数据，不代表实际运营效果。

### P2：用于继续解释产品能力

- 今日生成内容。
- 今日发布内容。
- GEO关键词进度。
- 知识库、平台发布、数据管理等工作模块入口。

### P3：不应占据首屏

- 详细技术参数。
- 全部系统功能清单。
- 复杂图表和历史趋势。
- 价格、合同和完整交付范围。
- 设置项、素材路径和系统管理信息。

## 四、卡片数量与内容密度

### 首屏建议数量

首屏最多保留：

- 1个设备与AI员工主视觉面板。
- 1个获客与成交信号面板。
- 1条工作流区域。
- 1组行动按钮。

也就是两个主要面板、一个流程区域和一组行动，不再使用六张独立指标卡组成主体。

### 全页建议数量

首页完整滚动区域最多保留四个核心内容块：

1. AI员工工作状态。
2. 今日获客与成交信号。
3. AI工作流。
4. 今日任务与下一步行动。

卡片只用于承载明确的单一信息，不在卡片内部继续嵌套卡片。每个区域都应有一个视觉中心，不以模块数量证明产品复杂度。

## 五、数据展示规则

### 1. 销售结果优先

首页指标顺序建议固定为：

1. 新增客户线索。
2. AI接待次数。
3. 待跟进客户。
4. 今日生成内容。
5. 今日发布内容。
6. GEO关键词进度。

前3项服务于“成交驾驶舱”，后3项服务于“运营解释”。

### 2. 演示数据必须明确

所有数字统一显示`演示数据`或`演示数据，不代表实际运营效果`。不要通过颜色、箭头或增长百分比制造真实经营成果的错觉。

### 3. 删除无依据的比较口径

如果没有真实的历史数据，不建议显示“较昨日”“提升比例”“增长趋势”等比较性表达。可以使用“今日运行中”“待销售确认”“知识库响应”等状态型文字。

### 4. 过程数据保持克制

内容生成量、发布量和GEO进度可以保留，但应作为辅助信号。`GEO关键词进度 286 / 500`应明确对应“首个季度关键词及关联词布局”，不能被理解为排名、询盘或成交保证。

## 六、按钮布局与交互优先级

### 主按钮

`开始客户演示`

点击后直接进入全屏演示流程。按钮应在首屏清晰可见，并成为销售人员最自然的下一步动作。

### 次按钮

`配置当前企业`

用于在见客户前录入企业名称、行业、产品、目标客户等信息。它的视觉权重低于主按钮，但必须方便销售快速找到。

### 辅助按钮

`查看今日任务`

用于查看待跟进客户和当天需要人工处理的事项。建议放在下方行动区或今日任务区域，不与开始演示争夺首屏焦点。

### 顶部工具按钮

全屏、帮助和系统设置继续保留在顶部工具区。它们是系统级操作，不应与首页核心销售动作混排。

## 七、动效建议

整体动效以“设备正在工作、流程正在运行、销售可以继续操作”为目标，避免把页面做成自动播放的PPT。

### 建议保留

- 首次进入时设备和主视觉轻微淡入、缩放归位。
- AI员工在线状态使用低频、克制的状态呼吸效果。
- 核心数字首次出现时使用短时数字增长，之后保持稳定。
- 工作流节点按业务顺序依次点亮，连接线只在节点激活时出现轻微亮度变化。
- 鼠标悬停或点击按钮时给出短促的位移、亮度和状态反馈。
- 进入客户演示后，以遮挡、推进和节点激活完成场景切换。

### 建议删除或限制

- 卡片依次从四周飞入。
- 图标持续漂浮和大面积发光边框。
- 弹跳式按钮、夸张缩放和高频粒子。
- 全屏自动循环的数字滚动。
- 与业务无关的背景光线和装饰性动画。

所有动效都应服务于信息顺序，动画结束后页面仍应保持清晰、安静和可操作。

## 八、保留、删除与隐藏建议

### 保留

- 深黑、深蓝、冰蓝为主的企业级视觉体系。
- 左侧导航和顶部全局状态栏。
- 数员科技品牌、正式Logo和当前企业信息。
- 黑色服务器机箱款AI员工一体机。
- AI机器人、在线状态和本地运行状态。
- 开始客户演示、企业配置、今日任务三个操作入口。
- AI工作流和企业获客链路。
- 演示模式、演示数据和合规说明。

### 删除或合并

- 删除重复出现的`开始客户演示`主按钮，仅保留一个首要入口。
- 合并六张等权指标卡，改为一个“今日获客与成交信号”区域。
- 删除没有真实历史数据支撑的“较昨日持续运行”等比较文案。
- 将工作流末端的`成交`从已完成状态改为`进入成交环节`或`待人工推进`。
- 减少英文眉题和技术化标签，避免影响老板阅读中文主信息。

### 默认隐藏或下沉

- 详细内容生产、发布记录和GEO进度。
- 完整技术参数和本地部署说明。
- 详细历史趋势、平台细分数据和系统管理信息。
- 价格、合同条款和全部交付清单。

这些内容可以通过后续模块、今日任务或继续演示进入，不应在首页第一眼同时出现。

## 九、老板第一眼看到什么

建议老板看到的顺序是：

1. 黑色AI员工一体机正在运行。
2. AI员工在线，服务当前企业。
3. AI正在持续产出内容、接待客户和提醒销售跟进。
4. 当前有多少新增线索、接待和待跟进事项。
5. 销售可以点击`开始客户演示`，继续查看完整过程。

不建议第一眼看到：

- 六个并列运营数字。
- 一屏完整功能菜单。
- 复杂趋势图和技术术语。
- 未经证实的增长率、询盘量、排名或成交数字。
- 需要销售先解释的系统设置和数据来源。

## 十、销售演示节奏建议

### 0—5秒：建立产品认知

展示设备、AI机器人和在线状态。让客户先确认“这是一个可以工作的AI员工系统”。

### 5—15秒：建立价值判断

突出新增线索、AI接待和待跟进三个销售信号，说明AI不是只生成文章，而是贯穿获客后的客户处理流程。

### 15—30秒：建立工作机制

沿着工作流展示企业知识库、内容生产、多平台发布、客户互动、AI接待和销售跟进。

### 30秒后：进入具体演示

点击`开始客户演示`，进入企业配置、内容生成、平台发布、GEO、智能接待、线索、报价、ROI和合作方案流程。

## 十一、适配与可读性原则

- 1440×900为主要销售演示尺寸，首屏完成价值判断和主操作。
- 1366×768下优先保证设备、三个核心数字和主按钮完整可见。
- 窄窗口下内容顺序固定为：设备与状态 → 获客信号 → 工作流 → 行动按钮。
- 不以缩小字号解决拥挤问题，优先减少内容和重新分配空间。
- 中文主标题、数字和按钮保持足够对比度；说明文字不抢主视觉。
- 任何数据说明和合规提示都不能遮挡设备、核心数字或主按钮。

## 十二、产品经理确认项

请在进入原型和开发前确认以下决策：

1. 首页主指标是否确定为“新增客户线索、AI接待次数、待跟进客户”。
2. GEO关键词进度是否放在首屏辅助区域，还是下沉到运营细节区域。
3. “查看今日任务”是否作为首页下方任务面板，还是仅作为一个导航入口。
4. 工作流最后一个节点是否使用“进入成交环节”或“待人工推进”，不直接展示已成交。
5. 是否确认首页只保留一个高权重的“开始客户演示”按钮。
6. 是否确认所有首页数字继续使用演示数据标识，不新增任何效果承诺。

## 十三、方案结论

V1首页应从“功能与数据展示页”转为“老板价值判断页 + 销售演示入口”。

核心原则是：

> 先让老板看到AI员工正在工作，再让老板看到它如何带来线索和跟进，最后引导销售进入完整演示。

本方案仅完成产品设计整理，不修改任何源代码、页面、数据库、接口或Electron配置。待产品经理确认后，再进入原型调整和开发排期。
