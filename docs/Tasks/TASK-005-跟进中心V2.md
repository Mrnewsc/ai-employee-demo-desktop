# TASK-005-跟进中心V2设计方案

## 文档信息

- 页面名称：跟进中心
- 方案版本：V2
- 页面定位：AI销售跟进工作台
- 文档状态：待产品经理评审
- 设计范围：跟进中心页面及其与客户线索、AI智能接待、报价管理的衔接
- 本文不涉及代码、接口、数据库或真实消息发送能力开发

## 一、页面目标

跟进中心不再是普通的待办列表，而是销售每天打开后即可做出行动判断的工作台。

销售进入页面后，需要马上知道：

1. 今天必须跟进哪些客户。
2. 为什么现在要跟。
3. 应该通过什么方式跟。
4. 第一段话应该怎么说。
5. 跟进完成后下一步是什么。

### 核心定位

> AI帮销售减少“忘记跟、不会跟、跟错时间”。

### 页面副标题

`AI根据客户状态和销售进度，整理今天最值得处理的跟进任务。`

### 核心业务链路

```text
客户线索
  → AI智能接待
  → 报价管理
  → 跟进中心
  → 下一轮接待 / 报价调整 / 持续培育
```

跟进中心的任务不是催促客户，而是让销售基于客户当前状态完成下一步合适动作。

## 二、页面整体布局

采用“顶部核心摘要 + AI今日跟进 + 任务列表与跟进详情双栏”的结构。

```text
┌──────────────────────────────────────────────────────────────┐
│ 页面标题 / 副标题 / 演示数据                    生成今日任务 │
├────────────────┬────────────────┬────────────────┬──────────┤
│ 今日必须跟进   │ 报价待回复     │ 需求待确认     │ 超时未处理 │
├─────────────────────────────────────────────────────────────┤
│ AI今日跟进：建议优先处理3家客户                  查看全部 → │
├──────────────────────────┬──────────────────────────────────┤
│ 左侧：跟进任务列表约40%    │ 右侧：跟进详情工作区约60%          │
│ 筛选 / 排序 / 任务卡片      │ 为什么现在跟 / 客户状态              │
│                            │ 行为轨迹 / AI策略 / 建议话术         │
│                            │ 跟进记录 / 下一步动作                 │
└──────────────────────────┴──────────────────────────────────┘
```

### 桌面尺寸建议

- 设计基准：1440 × 900
- 重点适配：1366 × 768
- 左侧任务列表：约40%
- 右侧详情工作区：约60%
- 右侧详情内部滚动，页面不出现横向滚动
- 底部核心操作区属于详情工作区结构的一部分，不覆盖内容
- 页面进入或切换任务时，右侧详情滚动位置回到顶部

## 三、信息层级

### P0：第一眼必须看到

- 今日必须跟进数量
- 报价待回复数量
- 需求待确认数量
- 超时未处理数量
- AI今日跟进的优先客户
- 当前客户名称、优先级和当前状态
- `为什么现在跟`
- 主操作`记录已跟进`

### P1：用于判断跟进方式

- 建议跟进时间
- 建议跟进方式
- 最近沟通时间
- 当前需求和报价状态
- AI跟进策略
- AI建议话术

### P2：用于执行后续动作

- 行为/沟通时间轴
- 沟通结果
- 客户反馈
- 下一步
- 下次跟进时间
- 延后跟进、进入AI智能接待、查看报价

### P3：辅助信息

- 来源平台
- 负责人
- 企业规模
- 官网
- 详细客户字段
- 演示数据说明

跟进中心不展示成交金额预测、成交概率、销售排名或无依据的效率提升数字。

## 四、顶部核心摘要

顶部只展示与今天销售动作直接相关的四项摘要。

### 1. 今日必须跟进

- 数值示例：`6`
- 辅助文案：`AI已完成优先级判断 · 演示数据`
- 点击后：列表筛选为`今日待跟进`

### 2. 报价待回复

- 数值示例：`2`
- 辅助文案：`已发送等待反馈 · 演示数据`
- 点击后：列表筛选为`报价待回复`

### 3. 需求待确认

- 数值示例：`3`
- 辅助文案：`需要补充关键信息 · 演示数据`
- 点击后：列表筛选为`需求待确认`

### 4. 超时未处理

- 数值示例：`1`
- 辅助文案：`超过建议处理时间 · 演示数据`
- 点击后：列表筛选为超时任务

摘要区不使用：

- 较昨日上涨
- 成交金额预测
- 成交概率
- 销售排名
- 效率提升百分比

所有数字仅用于展示工作台的处理方式，不代表真实运营结果。

## 五、AI今日跟进

### 1. 区域定位

“AI今日跟进”是首屏的核心行动区，帮助销售直接看到今天最值得处理的客户，不需要先浏览全部任务。

标题：

`AI今日跟进`

副标题：

`建议优先处理3家客户 · 演示数据`

右侧入口：

`查看全部`

点击后列表切换为AI推荐优先排序，并默认打开第一位客户。

### 2. 推荐客户数量

默认展示3家，不超过3家，避免首屏信息密度过高。

每条推荐只承载销售当前需要的判断信息：

- A/B/C优先级
- 客户名称
- 当前状态
- 为什么今天要跟
- 建议跟进时间
- 建议方式
- 一条AI建议

### 3. 推荐项示例

#### A / 高优先

**金华某五金制品厂（演示客户）**

当前状态：`报价待确认`

为什么今天跟：`昨天已发送报价，当前还有工件尺寸和喷涂材料待确认。`

建议时间：`今天 14:00`

建议方式：`微信 + 电话`

AI建议：`先确认两个技术问题，不要直接催客户下单。`

#### B / 中高优先

**义乌某机械有限公司（演示客户）**

当前状态：`需求待确认`

为什么今天跟：`客户已查看自动化生产线资料，但目标产能和产线长度还没有确认。`

建议时间：`今天 15:30`

建议方式：`电话`

AI建议：`先确认产线条件，再判断是否需要调整基础方案。`

#### B / 中高优先

**佛山某家具制造企业（演示客户）**

当前状态：`AI接待后待跟进`

为什么今天跟：`AI已收集家具配件喷涂需求，但交付周期和工件尺寸仍待补充。`

建议时间：`今天 16:30`

建议方式：`微信`

AI建议：`用已收集的信息继续提问，不重复询问客户已经回答过的问题。`

### 4. 推荐理由规则

推荐理由只能来自明确的演示数据：

- 报价是否已经发送
- 哪些参数已经确认或仍待确认
- AI智能接待是否完成需求收集
- 客户是否收藏或查看过演示产品资料
- 最近一次销售沟通时间
- 当前跟进状态

不使用以下判断：

- 客户成交概率82%
- 客户一定会采购
- 客户已经决定付款
- 客户真实阅读次数（没有可靠数据时）
- 客户真实微信已读状态

## 六、左侧跟进任务列表

### 1. 列表定位

左侧是按行动优先级排列的任务列表，不做成传统日历或Excel待办表。每条任务都要帮助销售判断“现在是否需要处理”。

### 2. 默认字段

每条任务默认显示：

- 客户名称
- A/B/C优先级
- 当前状态
- 跟进原因
- 建议跟进时间
- 最近沟通
- 当前任务状态

详细的来源平台、企业规模、负责人和官网等信息进入右侧详情。

### 3. 任务卡片建议结构

```text
┌─────────────────────────────────────────────┐
│ A / 高优先                         今日待跟进 │
│ 金华某五金制品厂（演示客户）                  │
│ 报价待确认 · 今天14:00                       │
│ 原因：两个技术参数仍未确认                    │
│ 最近沟通：昨天16:20 · 报价已发送              │
└─────────────────────────────────────────────┘
```

卡片不放置大量字段，不把任务做成多列数据表。

### 4. 任务状态

任务状态包括：

- `今日待跟进`
- `即将到期`
- `已跟进`
- `等待客户`
- `需要人工介入`
- `延后处理`

禁止使用`已成交`。成交属于后续销售流程，不在跟进任务中提前展示。

### 5. 优先级表达

优先级必须同时显示文字和等级，不依赖颜色单独表达：

- `A / 高优先`：今天需要优先处理
- `B / 中高优先`：已有明确需求，建议当天完成
- `C / 培育`：适合持续内容和低频跟进
- `D / 低优先`：信息不足或暂不需要立即处理

颜色建议：

- A：低饱和绿色
- B：冰蓝
- C：低饱和橙色
- D：灰蓝

## 七、筛选与排序

### 1. 筛选项

保留以下筛选：

- 全部
- 今日待跟进
- 报价待回复
- 需求待确认
- 等待客户
- 已跟进

筛选使用紧凑的分段控件或两行筛选组，1366×768下不出现横向滚动条。

### 2. 排序项

支持：

- AI推荐优先
- 建议跟进时间
- 最近沟通
- 优先级

默认排序：

`AI推荐优先`

### 3. AI推荐状态

点击`查看全部推荐`或顶部AI今日跟进入口后：

- 列表只显示AI推荐优先任务。
- 排序切换为AI推荐优先。
- 右侧默认打开第一条A或B级任务。
- 页面显示低权重状态提示`当前为AI推荐优先视图`。
- 可以点击`查看全部任务`恢复完整列表。

## 八、右侧跟进详情工作区

### 1. 顶部标题区

默认进入某条任务时，首屏显示：

- 客户名称
- 演示客户标记
- A/B/C优先级
- 当前销售阶段
- 最近一次沟通
- 下一次建议跟进时间

示例：

```text
金华某五金制品厂（演示客户）
A / 高优先 · 报价待确认
最近沟通：昨天16:20 · 报价已发送
下一次建议跟进：今天14:00
```

详情内容内部滚动，切换任务后回到详情顶部。

### 2. 为什么现在跟

这是详情首屏的核心判断区，用一句话解释本次跟进的必要性。

示例：

`客户已收到报价，但关键参数仍未确认，建议今天完成技术信息补充，避免报价长期停滞。`

这句话必须体现客户状态和当前销售动作，不使用空泛的“促进成交”或“尽快下单”。

### 3. 客户当前状态

显示：

- 关注产品
- 当前需求
- 已确认信息
- 待确认问题
- 报价状态
- 最近动作

示例：

- 关注产品：自动喷涂设备
- 当前需求：五金配件喷涂，日产约3000件
- 已确认信息：主要生产金属配件，日产量约3000件
- 待确认问题：工件尺寸、喷涂材料、现场产线条件
- 报价状态：待人工确认
- 最近动作：昨天16:20已发送报价草案

未知信息统一显示：

`待确认`或`待补充`

### 4. 行为/沟通轨迹

使用紧凑时间轴，按时间从上到下排列：

```text
09:25  客户首次咨询                         演示数据
10:03  AI完成需求收集                       演示数据
11:20  创建报价草案                         演示数据
14:10  销售确认报价                         演示数据
昨天16:20  报价已发送                       演示数据
今天14:00  建议再次跟进                     演示数据
```

时间轴表达销售流程，不等同于真实微信聊天记录或真实客户已读记录。

## 九、AI跟进策略

### 1. 区域定位

这是跟进中心的核心辅助区域，帮助销售明确本次跟进的目标和边界。

标题：

`AI跟进策略`

辅助说明：

`AI基于当前演示客户状态整理建议，最终动作由销售决定。`

最多展示3条，不堆叠过多解释。

### 2. 三条策略结构

#### 本次跟进目标

`确认工件尺寸和喷涂材料。`

#### 不建议做什么

`不要直接询问“考虑得怎么样”，也不要在技术参数未确认前催促下单。`

#### 如果客户回复后的下一步

`客户确认参数后，重新核对产品配置和正式报价。`

策略必须根据当前客户状态动态变化：

- 报价已发送：优先确认报价相关问题和客户反馈。
- 需求待确认：优先补齐关键需求字段。
- 等待客户：保持低频跟进，不重复发送相同信息。
- 需要人工介入：转交销售或技术人员，不让AI继续做未经确认的判断。

## 十、AI建议话术

### 1. 设计目标

话术必须帮助销售开始一次具体、克制的沟通，不做强硬催单，不承诺未经确认的价格、交期或技术方案。

### 2. 报价已发送示例

> 您好，昨天给您发的方案您应该收到了。这边还有两个参数想跟您确认一下，一个是工件尺寸，一个是现在主要使用什么喷涂材料。我这边确认完，可以再帮您把设备配置核得更准确一些。

### 3. 需求待确认示例

> 您好，上次沟通了解到您主要关注自动化生产线。我想再确认一下目前的目标产能和产线长度，方便我们先判断基础方案是否适合您的现场条件。

### 4. AI接待后待跟进示例

> 您好，前面AI接待已经记录到您关注家具配件喷涂。为了继续匹配方案，想再确认一下工件尺寸和您期望的交付时间，我可以先把需要人工核对的内容整理出来。

### 5. 话术规则

- 至少带入客户当前产品、需求或最近动作中的一项。
- 不同客户不能全部使用同一段话术。
- 不使用“马上下单”“最后机会”“考虑得怎么样”等强催表达。
- 不承诺正式报价、交付周期、库存或技术可行性。
- 显示`AI生成建议 · 发送前请销售确认`。

提供按钮：

`复制话术`

只复制到本地剪贴板，不真实发送消息。

## 十一、本次跟进记录

### 1. 区域定位

在AI建议话术之后提供简洁的本地记录区，帮助销售把现场沟通结果沉淀为下一步动作。

### 2. 输入字段

销售可以填写：

- 沟通结果
- 客户反馈
- 下一步
- 下次跟进时间

字段默认留空或显示`待填写`，不能自动虚构客户反馈。

### 3. 演示保存

- 点击保存后显示`本次跟进记录已保存到本地演示状态`。
- 不写数据库。
- 不发送微信、短信、邮件或其他第三方消息。
- 页面刷新或关闭后的持久化能力不作为本轮验收要求。

## 十二、核心操作

右侧只保留与当前任务直接相关的操作。

### 主按钮：记录已跟进

点击后打开轻量确认区域，不直接改变为成交或完成销售。

确认区域包含：

#### 本次结果

- 客户未回复
- 已确认需求
- 需要修改方案
- 等待客户内部确认
- 其他

#### 下一步建议

- 明天继续联系
- 3天后跟进
- 等待客户回复
- 返回报价管理
- 返回AI智能接待

确认后：

- 当前任务状态变为`已跟进`或`等待客户`。
- 右侧显示下一次建议跟进时间。
- 本地演示提示记录成功。
- 不更新意向等级，不生成成交结果。

### 次按钮：延后跟进

点击后提供低干扰时间选择：

- 今天下午
- 明天
- 3天后
- 自定义日期

只更新本地演示的建议时间和任务状态`延后处理`。

### 次按钮：进入AI智能接待

适用于需求仍不完整的客户：

- 安全跳转到现有AI智能接待页面。
- 带入上下文的逻辑在本轮只做演示提示。
- 不修改数据库，不新增真实接口。

### 辅助按钮：查看报价

当当前任务来自报价流程时显示：

- 低于`记录已跟进`的视觉权重。
- 安全跳转到现有报价管理页面。
- 可显示提示`已准备打开当前演示报价`。

不增加删除客户、发送消息、导出报告等低频按钮。

## 十三、记录已跟进后的状态流转

```text
今日待跟进
  │ 记录已跟进
  ├───────────────┬─────────────────┐
  ▼               ▼                 ▼
已跟进        等待客户          需要修改方案
  │               │                 │
  │               └─ 延后提醒       ├─ 返回报价管理
  │                                 └─ 返回AI智能接待
  ▼
下一轮AI推荐 / 持续培育
```

### 状态说明

- `今日待跟进`：当前建议今天处理。
- `即将到期`：建议跟进时间临近。
- `已跟进`：销售已完成本次沟通记录。
- `等待客户`：已完成当前动作，等待客户反馈。
- `需要人工介入`：需要销售或技术人员判断。
- `延后处理`：销售选择了新的演示处理时间。

禁止在状态中出现`已成交`。

## 十四、页面状态

### 1. 默认状态

- 默认排序为AI推荐优先。
- 默认选中第一条A或B级任务。
- AI今日跟进展示3家客户。
- 右侧详情回到顶部。
- 首屏可见客户状态、为什么现在跟、客户当前状态和主操作。

### 2. AI推荐状态

- 列表只展示AI优先任务。
- AI今日跟进区域显示已选中的第一条客户。
- 右侧突出推荐理由和AI跟进策略。
- 允许恢复全部任务。

### 3. 无任务状态

显示：

`今天暂无待处理跟进任务`

辅助说明：

`可以查看等待客户或已跟进任务，继续维护客户关系。`

不虚构新的任务数量。

### 4. 无详情状态

显示：

`选择一条跟进任务，查看AI建议和下一步动作。`

不显示空白大面板。

### 5. 已跟进状态

- 任务卡片显示`已跟进`。
- 主按钮显示低权重的`已记录`。
- 右侧保留本次记录和下一步时间。
- 不改变客户原有意向等级。

### 6. 等待客户状态

- 任务状态显示`等待客户`。
- 话术区域提示降低联系频率。
- 操作重点变为查看客户反馈或设置下一次提醒。

## 十五、与其他模块衔接

### 1. 客户线索 → 跟进中心

从客户线索点击`加入今日跟进`后，跟进中心带入：

- 客户名称
- A/B/C/D优先级
- 推荐理由
- 当前需求
- 建议跟进时间
- AI建议话术

### 2. AI智能接待 → 跟进中心

当AI智能接待收集到客户需求但仍有关键字段待确认时，跟进中心显示：

- 需求待确认
- 需要确认的问题
- 建议通过AI智能接待继续完成信息收集

### 3. 报价管理 → 跟进中心

当报价已发送或等待人工确认时，跟进中心带入：

- 客户名称
- 报价编号
- 产品方案
- 报价状态
- 已确认和待确认条件
- 建议跟进原因

### 4. 跟进中心 → AI智能接待

当任务需要补充需求时：

- 进入AI智能接待。
- 保留当前客户上下文的演示提示。
- 不自动向客户发送消息。

### 5. 跟进中心 → 报价管理

当任务需要调整方案时：

- 查看或进入报价管理。
- 打开相关演示报价逻辑。
- 报价仍需销售人工确认，不自动修改正式价格。

### 6. 本轮衔接范围

本轮只设计安全的前端跳转和演示状态提示，不设计真实的跨页面数据传递、数据库字段或接口协议。

## 十六、演示数据边界

### 必须标注

- 页面右上角或核心区域显示`演示数据，不代表实际运营效果`。
- 客户名称旁显示`演示客户`。
- 时间轴、报价状态、AI建议和推荐理由属于演示数据。
- AI话术显示`AI生成建议 · 发送前请销售确认`。
- 复制话术只复制本地文本，不代表已经发送。

### 禁止出现

- 虚构真实客户回复
- 虚构客户已读或阅读消息
- 虚构成交概率
- 虚构成交结果
- AI自动给客户发消息
- AI自动决定销售策略
- 虚构真实微信聊天记录
- 自动承诺价格、交期、库存或技术可行性
- 将“已跟进”表述为“已成交”

### 推荐表达

- 建议跟进
- 待客户回复
- 需求待确认
- 建议人工介入
- AI辅助建议
- 演示客户
- 演示数据，不代表实际运营效果

## 十七、视觉规范

### 色彩

- 深黑：`#05070D`
- 深蓝：`#071A3A`
- 科技蓝：`#1267FF`
- 冰蓝：`#6FB7FF`
- 主文字：`#F2F6FF`
- 次文字：`#AEB8CA`
- 高优先：低饱和绿色
- 待确认：低饱和橙色
- 等待客户：冰蓝
- 已完成：灰蓝或低饱和绿色

### 组件原则

- 不使用CRM Excel风格的满屏表格。
- 不用整页日历替代任务判断。
- 不使用白色大卡片。
- 推荐区域使用少量紧凑面板，不堆叠大量任务卡片。
- 任务卡片保留足够留白，优先展示客户、状态、原因和时间。
- 右侧详情按“为什么现在跟 → 客户状态 → 轨迹 → AI策略 → 话术 → 记录”排列。
- 状态同时使用文字和颜色，不依赖颜色单独表达。
- 不使用Emoji，图标统一使用现有Lucide图标体系。
- 1366×768下筛选项合理换行，不出现页面级横向滚动。

### 动效建议

- 页面进入时AI今日跟进和第一条任务短距离淡入。
- 切换任务时右侧详情轻微交叉淡入，并回到顶部。
- AI策略和话术不使用跳动、粒子或大面积扫描动画。
- 记录已跟进和延后跟进使用按钮状态变化与轻量提示反馈。
- 复制话术只显示短暂的本地复制成功提示。

## 十八、验收标准

1. 页面名称为“跟进中心”，副标题清楚表达AI辅助销售跟进定位。
2. 首屏只展示今日必须跟进、报价待回复、需求待确认、超时未处理四项摘要。
3. 存在AI今日跟进区域，默认展示3家优先客户。
4. 每条AI推荐都包含客户、当前状态、今天跟进原因、建议时间、建议方式和AI建议。
5. 页面主体采用左侧任务列表加右侧详情工作区，不使用传统日历或Excel表格作为主视觉。
6. 左侧任务卡片能看懂客户、优先级、原因、建议时间、最近沟通和任务状态。
7. 默认排序为AI推荐优先，筛选项保持全部、今日待跟进、报价待回复、需求待确认、等待客户、已跟进。
8. 右侧详情包含为什么现在跟、客户当前状态、行为/沟通轨迹、AI跟进策略和AI建议话术。
9. AI跟进策略最多展示3条，并区分本次目标、不建议做什么、客户回复后的下一步。
10. AI建议话术必须结合当前客户状态，不使用统一空泛的催单话术。
11. 复制话术只执行本地复制，不发送真实消息。
12. 跟进记录包含沟通结果、客户反馈、下一步和下次跟进时间。
13. 记录已跟进会先打开结果确认区域，再更新本地演示状态。
14. 延后跟进支持今天下午、明天、3天后和自定义日期等演示选项。
15. 右侧主操作为记录已跟进，延后跟进和进入AI智能接待为次级操作，查看报价保持低权重。
16. 客户可以沿着“线索 → 接待 → 报价 → 跟进 → 下一轮接待或报价调整”继续推进。
17. 所有客户、沟通轨迹、报价状态、AI建议和时间均明确属于演示数据。
18. 不显示成交概率、成交金额预测、虚构客户回复或真实微信聊天记录。
19. 在1440×900和1366×768下，任务列表、详情、筛选和操作按钮均可读且不发生页面级横向溢出。

## 十九、方案结论

跟进中心V2的核心不是让销售看到更多待办，而是让销售知道每一次联系的理由、方式和目标：

> AI告诉销售现在为什么跟，销售决定如何沟通；跟进完成后，系统继续推动下一步。

页面应成为客户线索、AI接待和报价流程之后的行动工作台，帮助销售减少遗漏与无效催促，同时保留人工判断和关系经营的主导权。

本方案仅完成产品设计整理，不修改任何代码、页面、数据库或接口。待产品经理评审确认后，再进入原型和开发阶段。
