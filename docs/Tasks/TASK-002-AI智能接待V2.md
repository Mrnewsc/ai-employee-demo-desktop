# TASK-002-AI智能接待V2设计方案

## 文档信息

- 产品：AI员工一体机销售演示系统
- 页面：AI智能接待
- 方案版本：V2
- 文档状态：待产品经理评审
- 方案类型：产品设计方案
- 本文不涉及代码、接口、数据库或页面开发

## 一、设计目标

AI智能接待V2不再只是一个聊天页面，而是销售人员展示“AI如何帮助企业完成一次真实产品需求处理”的核心成交页面。

客户发送一批资料后，页面需要让老板直观看到：

1. AI能够接收PDF、Word、Excel和图片等常见业务资料。
2. AI能够识别文件中的产品名称、型号和规格。
3. AI能够把客户需求与企业产品库进行匹配。
4. 对于没有直接匹配结果的产品，AI能够继续给出公开平台检索线索。
5. 销售最终获得一张可确认、可导出、可发送给客户的产品匹配结果表。

核心价值表达：

> 客户把资料发过来，AI先帮销售读懂资料、找出产品、匹配方案，销售再把时间用在确认需求和推进成交上。

AI不替代销售或技术人员。正式报价、定制方案、技术参数、交付周期和公开平台信息均需要人工确认。

## 二、页面定位

### 页面名称

AI智能接待 · 产品资料分析与匹配

### 页面首要任务

让销售在客户发来资料后，能够沿着一条明确的路径完成：

`接收文件 → AI识别 → 提取产品 → 匹配产品库 → 处理未匹配项 → 导出或发送结果`

### 页面不承担的任务

- 不在本页面配置真实第三方平台账号。
- 不在本页面生成未经人工确认的正式报价。
- 不自动向客户发送未经销售确认的结果。
- 不承诺公开平台检索结果的真实性、库存、价格或长期有效性。
- 不把AI输出包装成最终技术方案或成交承诺。

## 三、整体布局

保留当前深色企业级三栏工作台，不改变左侧导航和全局页面语言。页面主区域分为左、中、右三栏，底部设置固定操作区。

### 1. 页面顶部

顶部仅保留：

- 页面标题：`AI智能接待`
- 页面副标题：`接收客户资料，自动识别产品并匹配企业方案。`
- 当前客户名称和`演示客户`标记
- `演示数据，不代表实际运营效果`低权重提示
- 知识库连接状态

标题区不放复杂功能按钮，避免用户还没有上传资料就被多个操作分散注意力。

### 2. 左侧：客户文件区域

左侧区域是客户资料进入系统的入口，重点展示“客户发来了什么”。

#### 文件拖拽区

拖拽区建议放在左侧顶部，占据左栏约一半高度。

主提示：

`拖入客户资料，AI开始识别`

辅助说明：

`支持 PDF、Word、Excel、图片`

交互状态：

- 空状态：显示上传图标、支持格式和文件数量限制说明。
- 拖入状态：边框转为冰蓝色，显示“松开后开始分析”。
- 上传中：显示文件名、文件大小和当前处理状态。
- 上传完成：文件进入列表，列表按文件类型显示对应图标。
- 文件异常：显示“无法读取”，提供重新选择和删除入口。

#### 文件列表

每个文件项包含：

- 文件类型图标
- 文件名称
- 文件大小
- 接收时间
- 识别状态
- 删除或重新分析操作

建议演示文件示例：

- 产品目录.pdf
- 设备参数表.xlsx
- 客户现场照片.jpg
- 采购需求.docx

示例名称仅用于演示界面，不代表真实客户资料。文件列表最多突出3至5个文件，超过部分通过“还有N个文件”收起，避免左栏变成长列表。

#### 左侧底部客户上下文

保留当前客户信息，但压缩为一条简洁摘要：

- 客户名称
- 所属行业
- 主要需求方向
- 当前意向等级

客户聊天记录仍可作为辅助内容保留，但不应与文件分析主流程争夺左侧主要空间。

## 四、中间：AI分析过程

中间区域是页面的叙事主轴，重点展示AI正在如何处理客户资料，而不是只展示一个静态结果。

### 1. 分析过程标题

建议标题：

`AI正在理解客户资料`

辅助信息：

`从文件识别到产品匹配，所有关键步骤可追踪。`

### 2. 实时步骤

步骤按顺序展示，每一步包含状态、时间和简短结果。

#### 步骤一：接收客户文件

- 状态：已接收 / 处理中 / 完成
- 结果：已读取4个文件

#### 步骤二：识别文件内容

- PDF和Word：识别正文、表格和段落
- Excel：识别表头、产品行和规格字段
- 图片：识别图片中的产品文字、铭牌、外观和关键结构
- 结果：识别出产品资料、采购要求和图片信息

#### 步骤三：提取产品信息

展示AI逐项提取的结果：

- 产品名称
- 客户型号
- 关键规格
- 数量或产能
- 应用场景
- 客户备注

结果以少量流式字段出现，不使用大段连续文本。

#### 步骤四：匹配企业产品库

匹配顺序建议明确展示：

1. 型号精确匹配
2. 产品名称匹配
3. 规格和参数匹配
4. 同义词和行业表达匹配
5. 应用场景匹配

#### 步骤五：处理未匹配产品

如果企业产品库没有直接匹配项，进入扩展检索状态：

- AI图片识别
- 提取产品外观和可识别特征
- 检索公开平台同款或相似商品
- 返回候选结果供人工核验

#### 步骤六：生成产品匹配结果表

最终状态：

`已完成初步匹配，等待销售确认`

不要显示“已确定方案”或“自动报价完成”等容易造成误解的表达。

### 3. 分析区呈现方式

建议采用“步骤时间线 + 当前步骤结果”的组合：

- 左侧窄时间线显示六个步骤的先后关系。
- 右侧显示当前步骤的识别字段或匹配摘要。
- 已完成步骤保留结果摘要，可点击展开。
- 处理中步骤显示低频状态动画和“正在分析”。
- 失败步骤明确原因和下一步操作。

避免使用只有百分比变化的单一进度条。销售需要看到AI完成了什么，而不是只看到进度走到了多少。

## 五、右侧：产品匹配结果

右侧是页面最有成交力的结果区域，重点让老板看到“客户资料已经被转换成可行动的产品判断”。

### 1. 匹配摘要

顶部显示三个简洁摘要：

- 已识别产品：N项
- 已找到匹配：N项
- 待人工确认：N项

所有数量标注为演示数据，数字仅用于展示流程，不代表实际识别效果。

### 2. 产品匹配结果表

表格至少包含以下字段：

| 字段 | 设计说明 |
| --- | --- |
| 客户产品名称 | 来自客户文件或图片识别结果 |
| 客户型号 | 保留客户原始型号，无法识别时显示“待确认” |
| 我方对应产品 | 企业产品库中的候选产品 |
| 匹配度 | 显示高、中、低或百分比，必须标注为初步判断 |
| 是否找到 | 已找到、部分匹配、未找到 |
| 备注 | 展示规格差异、缺失字段或需要人工确认的内容 |

### 3. 匹配状态

#### 已找到

- 使用克制的绿色状态点。
- 显示对应产品和主要匹配依据。
- 操作：查看详情、确认匹配。

#### 部分匹配

- 使用冰蓝或橙色提示，不使用红色主视觉。
- 显示已匹配字段和缺失字段。
- 操作：补充资料、提交人工确认。

#### 未找到

- 显示“企业产品库暂无直接匹配”。
- 提供“查看公开平台候选”入口。
- 不显示“无法成交”或“客户流失”等负面表达。

### 4. 行展开详情

点击结果行后，在右侧或表格下方展开：

- AI识别到的原始内容
- 我方匹配依据
- 规格差异
- 需要客户补充的信息
- 建议下一步动作

展开内容不覆盖底部操作区，销售可以在查看详情后直接导出或发送。

## 六、未匹配产品的扩展检索

### 1. 触发条件

当企业产品库没有相同或相似产品，或者AI无法根据资料完成可靠判断时，显示：

`企业产品库暂未找到直接匹配，是否查看公开平台候选？`

必须由销售确认后再进入扩展检索，避免系统对所有资料自动发起外部查询。

### 2. 公开平台候选结果

候选结果以紧凑列表展示，不做成电商详情页。

每条结果包含：

- 商品图片
- 商品标题
- 来源平台，例如1688等公开平台
- 商品链接
- 识别到的相似特征
- 候选状态：待人工核验

公开平台结果必须明确标注：

`公开平台候选信息，仅供人工核验，不代表我方产品、价格或供货承诺。`

### 3. 候选结果操作

- 查看来源页面
- 加入匹配参考
- 标记为无关
- 请求客户补充图片或型号

不直接把公开平台商品作为我方产品推荐，也不自动复制平台价格和销售口径。

## 七、底部操作区

底部为固定的结果操作栏，保证销售完成分析后无需回到页面顶部寻找下一步。

### 主操作

`一键导出Excel`

导出内容包含：

- 客户产品名称
- 客户型号
- 我方对应产品
- 匹配度
- 是否找到
- 备注
- 待人工确认项

文件名建议：

`客户名称-产品匹配结果-演示数据.xlsx`

### 次操作

`一键发送客户`

点击后先打开发送预览，不直接发送。预览内容包含：

- 客户名称
- 已识别产品数量
- 已找到匹配数量
- 待确认项
- 给客户的补充资料请求

销售确认后才能发送。发送按钮在存在未确认的高风险字段时显示二次确认提示。

### 辅助操作

- `保存本次分析`
- `请求人工确认`
- `继续上传资料`

辅助操作不与导出和发送使用同等视觉权重。

## 八、典型演示流程

### 场景A：产品库中存在匹配

1. 销售打开AI智能接待页面。
2. 客户资料显示在左侧文件区。
3. AI依次完成文件识别和产品信息提取。
4. 中间分析区显示识别到产品名称、型号和规格。
5. 右侧结果表出现我方对应产品和匹配度。
6. 销售展开一条结果，查看匹配依据。
7. 销售点击`一键导出Excel`或打开`一键发送客户`预览。

### 场景B：产品库中没有匹配

1. 右侧结果表显示“企业产品库暂无直接匹配”。
2. 中间步骤进入“图片识别与公开平台候选”。
3. AI展示识别到的图片特征。
4. 右侧出现商品图片、商品标题、来源平台和商品链接。
5. 销售将候选结果加入参考或请求客户补充型号。
6. 页面始终提示公开平台结果需要人工核验。

## 九、页面状态设计

### 空状态

左侧突出拖拽上传区，中间显示流程说明，右侧显示：

`上传客户资料后，AI会在这里生成产品匹配结果。`

### 文件接收中

文件列表展示接收状态；中间显示“正在读取客户资料”；右侧保持空结果状态。

### 分析中

当前步骤高亮，已完成步骤保留结果。底部导出和发送按钮禁用，避免销售在结果尚未完成时操作。

### 部分完成

已经完成的产品先进入结果表；无法识别的项目标记为待确认，允许销售继续上传文件。

### 分析完成

右侧结果表可操作，底部导出和发送入口激活；页面显示“等待销售确认”，不显示自动成交状态。

### 分析失败

显示具体原因，例如文件损坏、图片过于模糊、表格字段无法识别。提供重新分析、替换文件和请求人工确认入口。

### 发送预览

发送前显示结果摘要和待确认项。用户取消预览时，原匹配结果和分析步骤不丢失。

## 十、视觉与交互原则

- 保留当前深黑、深蓝、冰蓝的企业级视觉。
- 三栏结构保持清晰，不增加第四栏。
- 左栏负责“客户资料”，中栏负责“AI过程”，右栏负责“可行动结果”。
- 表格是右栏主要内容，不用大量白色卡片分散注意力。
- AI头像固定出现在中间分析区标题或当前步骤旁，作为持续工作的身份标识。
- 文件图标、步骤图标和状态点统一使用Lucide图标，不使用Emoji。
- 分析步骤使用淡入、状态切换、流式字段和节点激活，不使用夸张的进度条或弹跳效果。
- 底部操作区保持稳定，不因表格展开、文件增加或候选结果出现而跳动。
- 任何长文件名、商品标题和备注都必须支持截断后展开，不能造成页面横向溢出。
- 表格列在较窄窗口中优先保留客户名称、我方产品、匹配度和是否找到。

## 十一、信息与合规边界

- 所有文件和分析结果在第一阶段仅作为本地演示数据。
- 页面不得伪造真实客户文件、真实识别数量或真实平台搜索结果。
- 公开平台候选必须显示来源平台和链接，并标注需要人工核验。
- 不展示公开平台未验证的价格、库存、联系方式或供货承诺。
- 不自动发送客户消息，发送前必须由销售确认。
- 不把匹配度等同于技术可行性、报价确定性或成交概率。
- 正式报价、定制方案、交付周期和技术配置继续由销售及专业人员确认。
- 保留“演示数据，不代表实际运营效果”提示，但不让提示遮挡主结果。

## 十二、产品经理验收标准

1. 首次进入页面能够明确看出文件上传、AI分析和产品匹配三步关系。
2. 左侧能够直观理解客户发送了哪些文件。
3. 中间能够看到AI完成了哪些识别和匹配步骤，而不是只有一个加载状态。
4. 右侧能够看到包含六个必要字段的产品匹配结果表。
5. 产品库没有匹配时，能够进入公开平台候选结果，但不会被理解成我方正式产品。
6. 底部能够找到导出Excel和发送客户两个核心动作。
7. 发送前必须有预览和人工确认，不能自动发送。
8. 页面不增加新的导航层级，不破坏当前AI智能接待的客户聊天、画像和人工转交能力。
9. 页面保持三栏深色企业软件视觉，不变成上传工具或电商搜索页面。
10. 所有状态、数据、链接和结果都有清晰的演示或人工确认边界。

## 十三、方案结论

AI智能接待V2的核心不是“AI会聊天”，而是“AI能够把客户资料转成销售可以继续推进的产品匹配结果”。

页面应该围绕一条成交叙事展开：

> 客户发资料，AI读资料；AI找产品，销售确认结果；结果可导出，也可在确认后发送给客户。

本方案仅完成产品设计整理，不修改任何代码、页面、数据库或接口。待产品经理评审确认后，再进入交互原型和开发排期。
