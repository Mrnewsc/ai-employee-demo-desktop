# REAL-AI-001F-R1 Windows手工验收清单

> 仅记录 Windows 打包版真人点击结果。所有文件均为脱敏测试资料，不记录 API Key、绝对路径或客户原文。

## 验收前准备

- 启动 `release/win-unpacked/数员科技 AI数字员工.exe`。
- 打开“AI智能接待”，切换到“资料分析与产品匹配”。
- 确认当前客户为金华演示客户，页面无白屏且关键按钮可见。
- 每个 Case 记录：开始时间、结束时间、失败步骤、错误码、截图文件名和人工决策。

## Case A：PDF单产品

1. 上传 `src/real-ai/fixtures/pdf/native-text/input.pdf` 并开始分析。
2. 预期识别 `SP-3000`，企业候选为产品库中的 `SP-3000`，匹配级别为精确匹配。
3. 展开结果并点击“查看原始依据”，预期看到 PDF 文件名、页码和原文依据。
4. 点击“确认匹配”，再点击“生成报价草案”。
5. 预期进入报价管理；产品 ID 来自企业产品库，单价为空并要求人工填写。

## Case B：低质量OCR

1. 上传 `src/real-ai/fixtures/images/product-list/input.png` 并开始分析。
2. 预期客户识别型号保持 `9P-3000`，显示 OCR 不确定和待人工确认。
3. 若出现 `SP-3000` 候选，匹配依据必须来自产品名称、规格、应用等非型号信息，级别不得为精确匹配。
4. 查看 Evidence，确认原始 `9P-3000`、图片来源和低置信度仍保留。
5. 人工选择或确认企业产品 `SP-3000`，再生成报价草案。
6. 预期报价使用企业产品 `SP-3000`；分析 Evidence 中仍为原始 `9P-3000`。

## Case C：多产品

1. 同时上传 `case-c-exact.xlsx`、`case-c-conflict.xlsx` 和 `case-c-none.xlsx`（位于 `src/real-ai/pipeline/fixtures/`）。
2. 预期分别出现有候选、需人工确认和未找到状态。
3. 在所有产品处理完成前，“生成报价草案”必须禁用。
4. 对有候选项确认，对需确认项人工选择，对 none 项标记未找到。
5. 全部决策完成后按钮解锁；none 项不得进入报价。

## Case D：硬规格冲突

1. 使用 Case C 中型号相同但功率或工作宽度冲突的产品。
2. 预期展开详情后显示冲突字段、客户值和产品库值。
3. 该项不得显示精确匹配，必须等待人工确认。

## Case E：空产品库

1. 使用隔离的空产品库测试环境上传 PDF。
2. 预期解析和提取完成后提示“尚未配置企业产品库”。
3. 预期保留已识别产品数量，不出现任何 Demo 候选，不允许生成报价。

## Case F：无API Key

1. 在隔离测试环境临时移除 DeepSeek 配置后上传 PDF。
2. 预期解析成功，提取阶段显示 `AI_NOT_CONFIGURED`。
3. 不得出现 Mock、Demo 或固定匹配结果。测试后恢复环境配置，不记录 Key。

## Case G：取消

1. 图片进入 OCR 阶段时点击“取消分析”，等待 3 秒。
2. PDF 进入“提取产品信息”阶段时点击“取消分析”，等待 3 秒。
3. 两次均应保持“已取消”，不得迟到变成完成，不得出现匹配或报价结果。

## Case H：跨文件同产品

1. 同时上传 `src/real-ai/fixtures/pdf/native-text/input.pdf` 和 `src/real-ai/pipeline/fixtures/case-h-same-product.xlsx`。
2. 预期最终只显示一个合并后的产品。
3. 打开 Evidence，预期同时看到 PDF 和 XLSX 两个独立文件来源。
4. 相同文字来自不同文件时必须显示为两条来源，不得只保留第一条。

## 分辨率与安全检查

- 在 1366×768 和 1440×900 下重复 Case A 的结果展开、Evidence 和报价按钮操作。
- 页面不得横向滚动，底部操作区不得遮挡结果。
- Renderer、错误详情和报告中不得显示 API Key、Authorization 或绝对本地路径。

## 结论规则

- 未实际点击的 Case 只能记录为“待验收”，不能写“通过”。
- 任一 P0 Case 失败，REAL-AI-001F-R1 结论必须为 B。
