### 4.3 时间顺序核对

当前代码中的时间记录为：

1. 09:12 查看自动喷涂设备内容。
2. 09:25 主动咨询日产量。
3. 10:03 AI完成基础需求收集。
4. 10:20 客户线索显示等待销售处理。
5. 今天10:24 客户线索显示主动咨询日产量。
6. 今天10:30 Q-2026-001 创建报价。
7. 跟进中心记录 11:20 创建报价草案。
8. 跟进中心记录 14:10 销售确认报价。
9. 跟进中心记录昨天16:20 报价已发送。
10. 跟进中心建议今天14:00再次跟进。

发现明确冲突：

- “昨天16:20 报价已发送”早于“今天10:30 创建报价”，时间倒置。
- 客户线索10:20/10:24仍处于等待销售处理或待报价，但跟进中心已进入报价发送后的跟进阶段。
- 报价列表 Q-2026-001 当前为“待人工确认”，跟进中心却以“昨天已发送报价”为推荐理由。
- 跟进中心的 11:20、14:10 没有和报价管理的“今天10:30”使用同一套时间记录。

### 4.4 状态顺序核对

理想状态应为：

`待报价 → AI接待完成/需求待确认 → 待人工确认 → 已确认待发送 → 已发送 → 待跟进`

当前页面实际表现为：

- 客户线索：待报价。
- AI智能接待：已完成默认对话和资料匹配，但没有把状态写回报价或线索。
- 报价管理：待人工确认。
- 跟进中心：今日待跟进，当前状态为报价待确认，但理由和轨迹又表示报价已发送。

因此当前主客户存在 P0 状态冲突。

## 6. 页面跳转检查

| 跳转 | 当前实现 | 结果 |

| 客户线索 → AI智能接待 | 调用 `navigate('reception')` | 可跳转，但没有传递选中客户，AI页默认打开金华客户 |
| 客户线索 → 报价管理 | 调用 `navigate('quotes')` | 可跳转，但没有传递选中客户或报价编号，默认打开 Q-2026-001 |
| AI智能接待 → 报价管理 | 当前页面没有直接创建报价/进入报价按钮 | 缺少明确的后续报价入口 |
| 报价管理 → 跟进中心 | 设置本地状态后调用 `navigate('followups')` | 可跳转，但跟进中心默认打开 follow-001，不保留当前报价客户 |
| 跟进中心 → AI智能接待 | 调用 `navigate('reception')` | 可跳转，但默认打开金华客户 |
| 跟进中心 → 报价管理 | 调用 `navigate('quotes')` | 可跳转，但默认打开 Q-2026-001 |

结论：路由层面能打开页面，但业务上下文未传递。当前所有“已带入当前客户上下文”的通知属于演示提示，不等同于实际带参跳转。

## 7. 文案与状态冲突

### P0

1. 金华客户报价管理显示“待人工确认”，跟进中心却写“昨天已发送报价”。
2. 金华客户线索仍为“待报价”，但跟进中心已进入发送报价后的跟进阶段。
3. 金华客户的报价创建时间和跟进时间轴顺序倒置。
4. 佛山客户客户线索产品与报价/跟进产品不一致。

### P1

1. 义乌和佛山切换到AI智能接待后仍显示金华客户的对话、画像和资料分析结果。
2. AI智能接待没有直接进入报价的动作，主链路需要销售手动从导航进入报价管理。
3. 客户线索、报价管理、跟进中心各自维护本地状态，状态更新不会回写其他模块。
4. 报价管理“加入跟进”可以从草稿或待人工确认状态直接进入跟进，可能绕过人工确认和发送环节。
5. 跟进中心页面阶段条把当前阶段固定显示为“跟进”，没有使用每条任务数据中的实际阶段；义乌和佛山会出现阶段偏后。
6. “是否接入现有生产线”和“现场产线条件”表达相近但未统一，容易让客户误以为是两个不同待确认项。
7. AI分析结果中的3项产品没有明确说明哪一项进入报价草案，当前只通过金华主客户的默认报价间接衔接。

### P2

1. 行业和地区只在客户线索页完整展示，AI接待、报价和跟进未完整沿用。
2. 报价和跟进存在嘉兴、宁波孤立客户，页面上没有“未完成前置链路”的说明。
3. 客户线索部分行为时间和跟进中心时间采用不同叙述，后续统一数据源后应只保留一套时间字段。

## 8. 演示数据边界检查

通过项：

- 客户名称使用“某”类演示名称，没有冒充真实客户案例。
- 客户线索、AI接待、报价和跟进页面均有演示数据提示或演示客户标记。
- 报价金额在报价列表、详情和发送预览中标记为演示数据。
- AI匹配度使用高/中/未找到等状态，没有展示无依据的成交概率。
- 联系人和联系电话在统一配置中仍为下划线占位符，没有擅自编造电话。
- `src` 运行时内容未检出旧版80、60、50、190询盘承诺，也未检出QQ看点或视频号。
- 设计文档中出现的“成交概率”等内容属于被禁止的反例说明，不是当前运行页面文案。

需要注意：

- AI接待的公开渠道候选标注为演示信息和人工核验，边界清楚。
- 跟进中心时间线、AI判断和报价状态虽然标注为演示数据，但目前叙述像一条真实已发生的客户轨迹，时间和状态修正前不宜对外解释为正式记录。

## 9. 建议修复项

### P0：产品经理确认后优先修复

1. 统一金华客户的唯一时间线，消除“昨天已发送”早于“今天创建报价”的倒置。
2. 统一金华客户的当前状态：在报价尚未人工确认前，不应在跟进页显示已发送报价后的跟进理由。
3. 将佛山客户在客户线索、AI接待、报价和跟进中的需求产品统一为同一个产品名称。
4. 明确AI智能接待完成后进入报价的业务出口，并确保出口对应当前客户和匹配产品。

### P1：主链路修复后处理

1. 为四个模块建立统一的本地演示客户上下文，至少共享客户ID、产品、已确认需求、待确认需求、当前阶段和最近动作。
2. 所有跨页跳转携带客户ID或报价编号，进入目标页面后选中对应客户，不再默认回到金华客户。
3. 义乌和佛山分别补齐与其自身产品相符的AI对话、画像、资料分析和匹配结果。
4. 约束报价状态流转：待人工确认 → 已确认待发送 → 已发送 → 待跟进；未发送前不直接进入发送后的跟进状态。
5. 跟进中心使用任务自身阶段渲染阶段条，避免所有客户都显示“跟进”。
6. 统一待确认字段文案，建议统一为“工件尺寸、喷涂材料、现场产线条件”。

### P2：体验和数据治理

1. 补充AI接待、报价和跟进中的行业与地区展示，保持客户识别信息完整。
2. 对没有完整前置链路的嘉兴、宁波记录增加“独立演示记录”标识，或暂不放入核心销售链路。
3. 统一演示时间字段格式与来源，避免同一客户在多个页面出现不同时间。
4. 将演示客户数据抽到统一本地数据文件，减少页面内重复常量。

## 10. 建议验收标准

修复后应满足：

1. 选择任一演示客户，从客户线索进入AI接待、报价和跟进后，四个页面仍保持同一客户。
2. 客户名称、行业、地区、需求产品、已确认需求和待确认需求在四页一致。
3. AI匹配的产品型号可以明确进入对应报价草案，报价产品不再出现跨客户或跨产品复用。
4. 时间顺序满足：产生线索 → AI接待 → 创建报价 → 人工确认 → 发送报价 → 跟进。
5. 状态顺序满足：待报价 → 需求确认 → 待人工确认 → 已确认待发送 → 已发送 → 待跟进。
6. 客户线索、AI智能接待、报价管理、跟进中心的跳转均保留客户上下文。
7. 所有金额、行为、时间线、AI判断和客户名称继续保持演示数据边界。
8. 不出现旧版80、60、50、190询盘承诺、QQ看点、视频号、虚构联系方式、虚构成交概率或成交承诺。
