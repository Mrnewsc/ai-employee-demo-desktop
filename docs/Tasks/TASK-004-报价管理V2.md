# TASK-004-报价管理V2设计方案

## 文档信息

- 页面名称：报价管理
- 方案版本：V2
- 页面定位：AI辅助报价工作台
- 文档状态：待产品经理评审
- 设计范围：报价管理页面及其与客户线索、AI智能接待、跟进中心的衔接
- 本文不涉及代码、接口、数据库或真实报价能力开发

## 一、页面目标

报价管理页不再只是报价记录列表，而是销售将客户需求整理成“可确认报价草案”的工作台。

销售进入页面后，需要快速完成以下判断：

1. 哪些报价等待人工确认。
2. 当前报价对应哪个客户和哪项需求。
3. 产品方案、配置和报价条件是否完整。
4. AI检查发现了哪些待确认问题。
5. 下一步应该保存、确认、预览发送，还是加入跟进。

### 核心定位

> AI负责整理需求、匹配产品和生成报价草案；销售负责确认价格、配置、交期和发送。

### 页面副标题

`根据客户需求和产品方案，快速生成并管理报价草案。`

### 核心业务链路

```text
客户需求
  → AI整理需求
  → 匹配产品方案
  → AI生成报价草案
  → 销售人工确认
  → 发送客户预览
  → 确认发送
  → 加入跟进
```

AI始终输出“草案”和“检查结果”，不直接决定正式价格，不替销售确认技术可行性，也不自动发送报价。

## 二、页面整体布局

采用“顶部摘要 + 左侧报价列表 + 右侧报价详情与编辑工作区”的结构，不使用传统财务软件或Excel大表格作为主视觉。

```text
┌────────────────────────────────────────────────────────────────┐
│ 页面标题 / 当前企业 / 演示数据                  新建报价草案   │
├────────────────┬────────────────┬────────────────┬────────────┤
│ 待确认报价     │ 今日新增报价   │ 等待客户回复   │ 即将到期报价 │
├────────────────────────────────────────────────────────────────┤
│ 左侧：报价列表约35%                │ 右侧：报价详情与编辑约65% │
│ 筛选 / 排序 / 报价卡片              │ 客户信息 / 需求摘要        │
│                                    │ 产品方案 / 报价条件        │
│                                    │ AI报价检查 / 方案说明      │
│                                    │ 保存 / 确认 / 发送 / 跟进   │
└────────────────────────────────────────────────────────────────┘
```

### 桌面尺寸建议

- 设计基准：1440 × 900
- 重点适配：1366 × 768
- 左侧报价列表：约35%
- 右侧详情工作区：约65%
- 详情区内部滚动，页面不出现横向滚动
- 底部操作区属于右侧详情结构的一部分，不覆盖报价内容

## 三、信息层级

### P0：第一眼必须看到

- 待确认报价数量
- 今日新增报价数量
- 等待客户回复数量
- 即将到期报价数量
- 当前选中客户名称
- 报价总额和报价状态
- 主操作“确认报价”

### P1：用于确认报价是否可推进

- 客户当前需求
- AI整理的需求摘要
- 产品名称、型号、配置、数量、单价和小计
- 有效期、交付周期、付款方式
- AI报价检查提醒

### P2：用于完善和发送

- 质保/服务
- 备注
- 客户可读的方案说明草案
- 发送预览
- 加入跟进

### P3：辅助信息

- 报价编号
- 创建时间
- 最近动作
- 来源模块
- 演示数据说明

页面不展示成交金额预测、成交概率、预计收益或没有依据的成本节省数据。

## 四、顶部核心摘要

顶部只保留四项与报价推进直接相关的摘要，不做销售额大屏。

### 1. 待确认报价

- 数值示例：`2`
- 辅助文案：`需要销售确认 · 演示数据`
- 点击后：列表筛选为`待人工确认`

### 2. 今日新增报价

- 数值示例：`3`
- 辅助文案：`今日创建 · 演示数据`
- 点击后：列表按最近新增排序

### 3. 等待客户回复

- 数值示例：`1`
- 辅助文案：`已发送待反馈 · 演示数据`
- 点击后：列表筛选为`待跟进`

### 4. 即将到期报价

- 数值示例：`1`
- 辅助文案：`请确认有效期 · 演示数据`
- 点击后：列表筛选为`即将到期`

摘要区不使用以下表达：

- 较昨日上涨
- 成交率提升
- 预计成交金额
- 预计回款金额

所有摘要数字仅用于现场功能演示，不代表真实业务结果。

## 五、左侧报价列表

### 1. 列表定位

左侧是帮助销售快速选择报价草案的行动列表，不是完整财务台账。每条报价使用紧凑的多行信息结构，突出客户、状态和下一步动作。

### 2. 报价条目字段

每条报价默认显示：

- 客户名称
- `演示客户`标记（演示数据）
- 报价编号
- 需求产品
- 当前金额
- 报价状态
- 创建时间
- 有效期
- 最近动作

其他详细字段进入右侧详情，不在列表中堆叠。

### 3. 报价条目建议结构

```text
┌──────────────────────────────────────┐
│ 待人工确认             报价草案       │
│ 金华某五金制品厂（演示客户）           │
│ Q-2026-001 · AI员工一体机              │
│ ¥39,800 · 有效期30天                   │
│ 最近动作：AI已整理需求 · 今天10:30      │
└──────────────────────────────────────┘
```

金额可以醒目，但字号不超过页面主标题，避免页面变成财务看板。

### 4. 报价状态

状态必须同时使用文字和低饱和状态色：

- `草稿`：尚未完成编辑
- `待人工确认`：AI已生成草案，等待销售确认
- `已发送`：已完成发送确认，等待客户反馈
- `客户已查看`：仅演示数据，不代表真实客户行为
- `待跟进`：报价已发送或客户已查看，需要销售继续推进
- `已失效`：报价超过有效期或被销售手动作废

禁止使用`已成交`。成交属于后续销售流程，不在报价管理页提前表达。

### 5. 筛选与排序

建议保留以下筛选：

- 全部
- 草稿
- 待人工确认
- 已发送
- 待跟进
- 已失效

排序支持：

- 待处理优先
- 最近更新
- 最近新增
- 有效期优先

默认排序为`待处理优先`，优先显示需要销售动作的报价草案。

## 六、右侧报价详情与编辑工作区

右侧详情是销售完成确认的主要区域。顶部压缩展示客户和报价状态，内容分为客户信息、需求摘要、产品方案、报价条件、AI检查和方案说明六个区块。

### 1. 标题区

标题区显示：

- 客户名称
- `演示客户`标记
- 报价编号
- 当前状态
- 最近动作时间

标题区右侧显示当前金额，但不使用夸张的大号数字。

示例：

```text
金华某五金制品厂（演示客户）
Q-2026-001 · 待人工确认
AI员工一体机 · ¥39,800 · 演示数据
```

### 2. 客户信息

显示：

- 客户名称
- 行业
- 联系人
- 当前需求

没有数据时统一显示：

`待补充`

不虚构联系人、电话、官网或企业规模。

### 3. 需求摘要

这是AI辅助报价的依据区。内容来自客户线索和AI智能接待中的已确认、待确认信息。

建议采用“已整理信息 + 待确认问题”的结构：

#### 客户需要

`自动喷涂设备`

#### 日产量

`约3000件`

#### 工件

`五金配件`

#### 关键要求

`运行稳定，可接入现有产线`

#### 待确认

`工件尺寸、喷涂材料、现场产线条件`

需求摘要必须明确“已确认”和“待确认”，不能把AI推测写成客户已经确认的信息。

### 4. 产品方案

产品方案以可编辑的方案行展示，不使用密集的财务表格。每行包含：

- 产品名称
- 产品型号
- 配置说明
- 数量
- 单价
- 小计

演示示例：

| 产品名称 | 产品型号 | 配置说明 | 数量 | 单价 | 小计 |
| --- | --- | --- | ---: | ---: | ---: |
| AI员工一体机 | 标准版 | 一体机设备、本地化部署、知识库配置 | 1 | ¥39,800 | ¥39,800 |

表格仅用于表达产品方案，不作为自动定价结果。单价和配置都应允许销售修改。

### 5. 报价条件

显示并允许销售人工编辑：

- 报价总额
- 有效期
- 交付周期
- 付款方式
- 质保/服务
- 备注

默认演示状态可以使用：

- 交付周期：`待人工确认`
- 付款方式：`待人工确认`
- 质保/服务：`三年设备质保，具体以正式合同为准`

系统不得把待确认条件自动转换成正式承诺。

### 6. 编辑原则

- AI生成的报价草案可以修改。
- 客户需求、产品配置、报价条件均需保留人工修改入口。
- 修改后显示`未保存修改`状态。
- 关闭或切换报价前，提示保存或放弃修改。
- AI不能直接发送未确认报价。

## 七、AI报价检查

### 1. 区域定位

AI报价检查是右侧的辅助判断区，用于帮助销售减少遗漏，不决定最终价格，不替代技术和商务确认。

标题：

`AI报价检查`

辅助说明：

`AI只检查完整性和前后一致性，正式报价由销售确认。`

### 2. 检查维度

AI只检查以下内容：

1. 客户需求是否完整。
2. 产品配置是否存在缺失。
3. 是否还有待确认问题。
4. 报价是否填写交付周期。
5. 报价是否填写付款条件。
6. 产品方案、数量、金额是否存在明显前后矛盾。

### 3. 演示检查结果

示例：

```text
AI报价检查 · 3项待人工确认

注意  客户工件尺寸仍未确认。
注意  当前报价未填写交付周期。
建议  发送前确认是否需要接入现有产线。
通过  产品数量与报价小计已完成基础校验。
```

检查结果使用“注意 / 建议 / 通过”文字和低饱和状态色，不使用夸张告警动画。检查结果应能点击定位到对应的需求字段或报价条件。

### 4. 检查状态

- `待检查`：报价草案尚未完成检查
- `存在待确认项`：有问题需要人工处理
- `已完成基础检查`：基础字段已检查，但仍需销售确认
- `人工已确认`：销售完成当前报价的人工确认

“已完成基础检查”不等于“技术方案已确认”或“价格已锁定”。

## 八、AI方案说明

### 1. 定位

AI生成一段客户可读的方案说明草案，帮助销售快速整理表达。它可以编辑，但不能绕过人工确认直接发送。

标题：

`客户方案说明草案`

辅助说明：

`可编辑内容，发送前请由销售确认。`

### 2. 演示文案

> 根据您目前提供的信息，我们已初步匹配自动喷涂设备方案。
>
> 当前方案按照日产约3000件、五金配件喷涂场景进行配置。
>
> 正式设备规格仍需确认工件尺寸、喷涂材料及现场产线条件。
>
> 最终配置、价格和交期以双方确认结果为准。

文案必须来自当前客户的产品、工况和已确认信息。遇到缺失数据时使用“待确认”，不补造参数、案例或交付承诺。

### 3. 编辑状态

- 默认显示AI草案。
- 销售点击编辑后进入文本编辑状态。
- 编辑后显示`已修改，待保存`。
- 保存草稿只保存本地演示状态。
- 发送预览使用当前已保存版本。

## 九、核心操作与状态流转

右侧底部只保留四个核心动作，按业务优先级排列。

### 1. 主按钮：确认报价

作用：

- 将报价从`草稿`或`待人工确认`推进到`人工已确认`或`已确认待发送`。
- 确认前检查报价条件是否完整。
- 如果仍有待确认项，显示提醒并允许销售返回修改。

确认报价不等于发送客户，也不等于成交。

### 2. 次按钮：发送客户

作用：

- 只能在报价人工确认后使用。
- 点击后打开发送预览抽屉或预览层。
- 预览中展示客户名称、方案说明、产品方案、报价条件和合规提示。
- 预览层提供`确认发送`和`返回修改`。

本轮设计中“确认发送”只模拟发送状态，不连接微信、邮件或其他第三方接口。

### 3. 次按钮：加入跟进

作用：

- 将报价状态推进到`待跟进`。
- 在跟进中心生成一个本地演示跟进任务。
- 默认带入客户名称、报价编号、最近动作和建议跟进原因。

不改变客户意向等级，不生成成交结果。

### 4. 辅助按钮：保存草稿

作用：

- 保存人工编辑后的报价内容。
- 状态保持为`草稿`或`待人工确认`。
- 给出明确的保存反馈。

### 5. 推荐按钮布局

```text
[确认报价]  [发送客户]  [加入跟进]  [保存草稿]
```

当报价尚未确认时，`发送客户`保持禁用或低权重，并在旁边提示：

`请先完成人工确认，再进行发送预览。`

## 十、报价状态流转

```text
草稿
  │ 保存草稿
  ▼
待人工确认
  │ 销售确认报价
  ▼
已确认待发送
  │ 打开发送预览 → 确认发送
  ▼
已发送
  │ 客户反馈或演示状态变化
  ├───────────────┐
  ▼               ▼
客户已查看       待跟进
  │               │
  └──────→ 跟进中心

超过有效期或销售手动作废 → 已失效
```

### 状态规则

- `草稿`：可以继续编辑，不能发送。
- `待人工确认`：AI完成需求整理或报价草案，等待销售确认。
- `已确认待发送`：销售确认了当前版本，等待打开发送预览。
- `已发送`：完成发送确认后的本地演示状态。
- `客户已查看`：仅本地演示状态，不能作为真实客户行为证明。
- `待跟进`：需要销售继续联系客户。
- `已失效`：不能继续发送，允许复制为新草案。

## 十一、页面状态

### 1. 默认状态

- 默认选中一条`待人工确认`报价。
- 右侧展示完整需求摘要、方案、AI检查和操作区。
- 默认排序为待处理优先。
- 页面右上角显示低权重的`演示数据，不代表实际运营效果`。

### 2. 无报价状态

显示：

`还没有报价草案`

辅助说明：

`可以从客户线索或AI智能接待创建一份报价草案。`

提供唯一主要入口：

`新建报价草案`

### 3. 未选择报价状态

右侧显示：

`选择一份报价草案，查看需求、产品方案和AI检查结果。`

不显示空白的大型表单。

### 4. 未保存修改状态

- 标题区显示`未保存修改`。
- 切换列表项时提示保存或放弃修改。
- 发送客户按钮保持不可用，直到当前版本保存并完成人工确认。

### 5. AI检查存在待确认项

- AI检查区保持可见。
- `确认报价`可以点击，但先展示待确认项清单。
- 销售可以返回修改，也可以确认“已知晓并人工核验”。
- 不自动填充交付周期、付款条件或技术参数。

### 6. 已失效报价

- 详情区显示失效原因和失效时间。
- 发送按钮不可用。
- 提供低权重操作`复制为新草稿`，生成新的本地演示报价编号。

## 十二、与其他模块衔接

报价页面在产品路径中的位置为：

```text
客户线索 → AI智能接待 → 报价管理 → 跟进中心
```

### 1. 从客户线索创建报价

进入报价管理时，建议带入：

- 客户名称
- 需求产品
- 已确认需求
- 待确认需求
- 当前意向等级
- 最近行为和推荐理由

报价页默认创建一条`待人工确认`草案，不直接生成正式报价。

### 2. 从AI智能接待生成报价

当AI智能接待完成产品匹配或需求收集后，可以将以下内容作为草案来源：

- 客户产品名称
- 客户型号或规格
- 我方对应产品
- 匹配状态
- 已确认配置
- 待人工确认问题

产品匹配结果只能作为报价草案输入，不能直接视为正式技术方案。

### 3. 进入跟进中心

点击`加入跟进`后，跟进中心可展示：

- 客户名称
- 报价编号
- 报价状态
- 最近动作
- 建议跟进时间
- 待确认问题
- 建议话术

跟进中心不显示虚构的客户反馈和成交结果。

### 4. 本轮衔接范围

本轮只完成页面逻辑和演示交互设计，不设计真实的跨页面数据传递、数据库字段或接口协议。

## 十三、演示数据边界

### 必须标注

- 报价列表或页面右上角显示`演示数据，不代表实际运营效果`。
- 客户名称旁显示`演示客户`。
- 客户查看状态标注`仅演示数据`。
- AI报价检查和方案说明标注为AI辅助草案。
- 金额、有效期、交付周期和付款方式标注为演示或待人工确认。

### 禁止出现

- AI自动决定正式价格
- AI自动承诺交付周期
- AI自动承诺技术可行性
- 自动发送报价
- 虚构真实成交金额
- 虚构客户真实查看记录
- 虚构库存、联系方式、付款结果或回款结果
- 用报价草案表述客户已经确定采购
- 用报价金额推导成交概率或收益预测

### 推荐表达

- 初步报价草案
- 待人工确认
- 待补充
- 待确认
- 仅演示数据
- 正式配置、价格和交期以双方确认结果为准
- 具体功能及交付范围以正式合同为准

## 十四、视觉规范

### 色彩

- 深黑：`#05070D`
- 深蓝：`#071A3A`
- 科技蓝：`#1267FF`
- 冰蓝：`#6FB7FF`
- 主文字：`#F2F6FF`
- 次文字：`#AEB8CA`
- 通过状态：低饱和绿色
- 注意状态：低饱和橙色
- 失效状态：灰蓝

### 布局与组件

- 左侧列表约35%，右侧详情约65%。
- 使用深色半透明面板和轻微边框，不使用白色大卡片。
- 报价金额醒目但克制，使用中等字号和货币符号，不做巨型财务数字。
- 产品方案使用稀疏的方案行，不做密集Excel表格。
- AI检查区使用窄边框和低饱和状态色，不使用大面积荧光红或发光框。
- 右侧操作区固定在详情底部，但必须为内容预留空间，不遮挡需求、检查和说明。
- 所有状态同时显示文字和颜色，不能只靠颜色表达。
- 图标使用现有Lucide图标体系，不使用Emoji。
- 页面不出现横向滚动，长客户名称和方案说明使用合理换行。

### 动效建议

- 页面进入时左侧列表和右侧详情短距离淡入。
- 切换报价时，详情内容做轻微交叉淡入，不使用大幅位移。
- AI检查结果按检查项顺序短暂出现，保持克制。
- 进入发送预览使用右侧抽屉或局部面板展开。
- 状态变化使用文字、边框和按钮状态变化表达，不使用粒子、弹跳或夸张进度动画。

## 十五、验收标准

1. 页面名称为“报价管理”，副标题清楚表达AI辅助报价定位。
2. 首屏只展示待确认报价、今日新增报价、等待客户回复、即将到期报价四项摘要。
3. 页面主体为左侧报价列表加右侧详情工作区，不使用传统大表格作为主视觉。
4. 左侧每条报价能看懂客户、编号、产品、金额、状态、时间和最近动作。
5. 报价状态只使用草稿、待人工确认、已发送、客户已查看、待跟进、已失效等状态，不出现已成交。
6. 右侧包含客户信息、需求摘要、产品方案、报价条件、AI报价检查和方案说明。
7. 需求摘要能区分已确认信息和待确认问题。
8. 产品方案中的名称、型号、配置、数量、单价和小计可被销售人工修改。
9. AI报价检查只做完整性和一致性提示，不自动决定价格或技术结论。
10. 客户方案说明为可编辑草案，发送前必须经过销售确认。
11. 右侧只保留确认报价、发送客户、加入跟进、保存草稿四个核心操作。
12. 发送客户前必须打开预览，并提供返回修改和确认发送两个选择。
13. 未人工确认时，发送客户不能直接执行。
14. 报价可以从客户线索和AI智能接待的产品需求进入草案逻辑。
15. 加入跟进后能够明确衔接跟进中心，但不虚构成交结果。
16. 所有金额、客户和查看状态都明确属于演示数据。
17. 不展示成交金额预测、成交概率、真实库存、联系方式或自动承诺。
18. 在1440×900和1366×768下，列表、详情、AI检查和底部按钮均可读，不发生页面级横向溢出。

## 十六、方案结论

报价管理V2的核心不是让AI替销售拍价格，而是让销售更快获得一份结构完整、问题透明、可以人工确认的报价草案：

> AI整理需求，销售确认方案；AI提示遗漏，销售决定是否发送。

页面最终应成为从客户需求到销售报价动作的工作台，并将报价自然推进到跟进中心，而不是报价记录的终点。

本方案仅完成产品设计整理，不修改任何代码、页面、数据库或接口。待产品经理评审确认后，再进入原型和开发阶段。
