# TASK-002-AI智能接待V2高保真UI设计

## 设计状态

- 页面：AI智能接待 V2
- 设计目标：高保真UI设计规范
- 视觉方向：Apple 产品发布会质感 + Linear 工作台效率
- 页面状态：待产品经理评审
- 本文仅为页面设计，不涉及代码、接口和实际开发

## 一、设计总纲

### 页面核心感受

客户把资料发给企业后，销售打开页面即可看到一条清晰、可信、可继续推进的智能处理链路：

> 文件已接收，AI正在理解资料，产品正在匹配，结果等待销售确认。

页面要像一套真正工作的企业级AI系统，不像上传组件、聊天机器人或电商搜索页。

### 视觉关键词

- 深色
- 克制
- 精准
- 有空间感
- 信息密度高但不拥挤
- 每一步都有状态反馈
- 重点结果始终可见

### 视觉禁区

- 大面积白色卡片
- 荧光描边和霓虹边框
- 多个彩色图标同时出现
- 夸张的AI粒子、扫描线和电路装饰
- 复杂渐变背景抢夺结果表注意力
- 像电商平台一样堆叠商品图片和价格
- 把匹配结果包装成正式报价或成交承诺

## 二、画布与空间结构

### 基准画布

- 设计基准：1440 × 900
- 适配画布：1920 × 1080、1366 × 768
- 页面背景：`#05070D`
- 主内容最大宽度：约 1480px
- 页面左右内边距：28—36px
- 栏间距：16px
- 面板圆角：14—18px
- 主要边框：1px，低透明度蓝灰色

### 页面分区

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 页面标题 / 当前客户 / 知识库状态 / 演示数据                         │
├───────────────┬────────────────────────┬─────────────────────────────┤
│ 客户文件       │ AI分析过程              │ 产品匹配结果                 │
│ 文件接收       │ 当前步骤                │ 摘要                         │
│ 文件列表       │ 识别字段                │ 匹配结果表                   │
│ 客户上下文     │ AI建议                  │ 未匹配候选                   │
├───────────────┴────────────────────────┴─────────────────────────────┤
│ 导出Excel                         发送客户 / 人工确认 / 继续上传资料  │
└──────────────────────────────────────────────────────────────────────┘
```

### 三栏比例

- 左侧：25%
- 中间：39%
- 右侧：36%

左侧承担输入，中间承担过程，右侧承担结果。右侧不应过窄，因为《产品匹配结果表》是页面最重要的成交证据。

## 三、顶部标题区

### 视觉结构

顶部高度约 72px，下方使用一条极弱分割线。

左侧内容：

- 小眉题：`AI RECEPTION / PRODUCT INTELLIGENCE`
- 主标题：`AI智能接待`
- 副标题：`接收客户资料，自动识别产品并匹配企业方案。`

右侧内容：

- 当前客户：`金华某五金制品厂（演示客户）`
- 知识库状态：蓝绿色状态点 + `企业知识库已连接`
- 低权重说明：`演示数据，不代表实际运营效果`

### 顶部层级

1. 页面标题最醒目。
2. 当前客户和知识库状态用于建立可信度。
3. 演示数据说明保持10px左右，不使用高亮底色，不抢主内容。

顶部不放“上传文件”“导出结果”等操作按钮。主要操作统一在底部固定操作区，避免页面出现多个行动起点。

## 四、左侧：客户文件工作区

### 左侧目标

让销售第一眼知道客户发来了哪些资料，当前资料是否已经被接收，以及AI是否可以开始分析。

### 1. 文件接收面板

面板标题：

`客户资料`

右侧辅助信息：

`4个文件`

#### 空状态

中心显示一个简洁的上传图标，下面两行文字：

`拖入客户资料`

`支持 PDF、Word、Excel、图片`

底部使用低权重文字：

`也可以点击选择文件`

空状态不放复杂说明，不展示技术术语。

#### 拖入状态

拖拽到区域内时：

- 面板边框变为冰蓝色。
- 背景出现很弱的蓝色内光。
- 中心文字变为：`松开后开始分析`
- 其他页面内容保持稳定，不发生尺寸跳动。

#### 已接收状态

上传区域缩小为面板顶部的轻量入口：

- `继续添加资料`
- `重新分析`

文件列表成为面板主体。

### 2. 文件列表

每个文件项高度约 52—60px，使用紧凑纵向列表。

文件项结构：

- 左侧文件类型图标
- 文件名
- 文件大小和接收时间
- 右侧识别状态
- 更多操作图标

示例：

| 文件 | 信息 | 状态 |
| --- | --- | --- |
| 产品目录.pdf | 4.8 MB · 刚刚接收 | 已识别 |
| 设备参数表.xlsx | 820 KB · 刚刚接收 | 已识别 |
| 客户现场照片.jpg | 2.1 MB · 刚刚接收 | 图片识别中 |
| 采购需求.docx | 96 KB · 刚刚接收 | 已识别 |

状态使用颜色区分，但不使用大面积彩色标签：

- 已识别：绿色小圆点
- 识别中：蓝色小圆点和轻微旋转状态
- 待确认：冰蓝色提示
- 读取失败：低饱和橙色提示

### 3. 客户上下文

文件列表下方显示一块低层级客户摘要：

- 客户名称
- 行业：五金制造
- 需求方向：自动喷涂设备
- 意向等级：中高

客户上下文不是独立大卡片，而是面板内的分组信息，避免左侧出现过多层级。

### 4. 左侧底部状态

保留一条轻量提示：

`资料仅用于本地演示，正式交付以客户配置为准。`

不放大段免责声明。

## 五、中间：AI分析工作区

### 中间目标

让销售看懂AI正在做什么，并且在每个关键节点看到一个具体结果。

### 1. 面板头部

左侧：

- 固定AI员工头像：深蓝圆角方形头像，使用Bot视觉符号。
- 标题：`AI正在理解客户资料`
- 辅助状态：`已接收4个文件 · 当前分析耗时 00:08`

右侧：

- 状态点：`分析中`或`分析完成`
- 一个小型暂停/继续图标按钮，仅在分析过程中出现

AI头像在页面中间区域固定出现，作为整个分析过程的身份标记。头像不漂浮、不大幅移动、不使用白色机器人图片作为主要背景。

### 2. 分析步骤时间线

使用纵向步骤线，位于中间面板左侧，宽度约 120px。

步骤名称：

1. 接收客户文件
2. 识别文件内容
3. 提取产品信息
4. 匹配企业产品库
5. 查询公开平台候选
6. 生成匹配结果

### 步骤状态表现

#### 已完成

- 蓝绿色状态点
- 步骤名称颜色变亮
- 右侧显示完成摘要

#### 当前处理

- 冰蓝状态点
- 状态点外圈有很弱的呼吸光
- 文字：`正在提取产品型号`
- 右侧实时显示最新识别字段

#### 未开始

- 灰蓝色空心点
- 文案保持低对比度

#### 需要人工确认

- 橙色小提示点
- 文案：`发现规格差异，等待确认`

### 3. 当前分析结果区

时间线右侧为动态内容区，每次只突出当前步骤的一个核心结果。

#### 文件识别结果

展示：

- 已读取：4个文件
- 可解析文本：3份
- 待图片识别：1张

#### 产品提取结果

使用紧凑字段列表：

- 产品名称：自动喷涂设备
- 客户型号：SP-3000
- 产能要求：约3000件/天
- 工艺场景：金属配件喷涂
- 关键规格：待确认

AI提取结果以“字段 + 内容”呈现，不显示长段AI思考文本。

### 4. AI思考过程

“AI思考过程”不展示模型内部隐私推理，也不展示冗长的逐字思考。只展示可审计的工作步骤和判断依据。

建议标题：

`AI工作判断`

显示三条可读信息：

- `已从客户资料中识别出3个产品条目`
- `正在使用型号、名称和关键规格匹配企业产品库`
- `当前有1个条目缺少完整规格，建议人工确认`

每条信息左侧使用状态图标，右侧可以显示`查看依据`。点击后展开来源文件和原始字段。

## 六、中间下部：AI建议区

### 设计目标

AI建议不是泛泛而谈的聊天回复，而是帮助销售决定下一步怎么推进客户。

### 建议面板标题

`AI建议`

副标题：

`基于客户资料和当前匹配结果`

### 建议内容结构

建议最多显示3条，第一条为主建议，其余为辅助建议。

#### 主建议

使用较明显但克制的蓝色背景：

`建议先确认客户型号 SP-3000 的工件尺寸和喷涂材料，再确认我方方案是否可以直接匹配。`

主建议右侧显示操作：

`生成确认话术`

#### 辅助建议

- `客户已提供日产量信息，建议将其加入匹配备注。`
- `有1项产品库未找到直接匹配，建议请求客户补充铭牌照片。`

### 建议原则

- 建议必须与当前资料和匹配结果相关。
- 不给出未经确认的正式报价。
- 不直接承诺技术可行性。
- 建议动作最多占一行，详细解释通过展开查看。

## 七、右侧：产品匹配结果区

### 右侧目标

让销售可以快速回答客户：哪些产品找到了，哪些产品需要确认，下一步应该做什么。

### 1. 面板头部

标题：

`产品匹配结果`

辅助信息：

`初步匹配 · 等待销售确认`

右侧操作：

- 筛选图标
- 展开/收起结果详情

### 2. 匹配摘要条

紧贴面板头部显示三个数字：

- 已识别：3项
- 已匹配：2项
- 待确认：1项

摘要条使用横向分隔，不做成三张独立卡片。

### 3. 产品匹配结果表

#### 桌面版字段

| 字段 | 宽度建议 | 视觉处理 |
| --- | --- | --- |
| 客户产品名称 | 18% | 主文字 |
| 客户型号 | 13% | 等宽感数字文字 |
| 我方对应产品 | 22% | 可点击展开 |
| 匹配度 | 12% | 状态文本 |
| 是否找到 | 13% | 小状态点 |
| 备注 | 22% | 可展开文本 |

#### 结果行示例

| 客户产品名称 | 客户型号 | 我方对应产品 | 匹配度 | 是否找到 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 自动喷涂设备 | SP-3000 | 自动喷涂设备标准方案 | 高 | 已找到 | 产能接近，尺寸待确认 |
| 自动化输送线 | AL-120 | 自动化生产线 | 中 | 部分匹配 | 需要确认线体长度 |
| 工件清洗设备 | 待识别 | 暂无直接匹配 | — | 未找到 | 建议补充铭牌或规格照片 |

### 4. 表格行状态

#### 已找到

- 行左侧细蓝绿色状态线。
- 匹配度显示`高`。
- 我方对应产品使用浅蓝色文字。

#### 部分匹配

- 行左侧使用低饱和橙色状态线。
- 备注优先显示缺失信息。
- 提供“请求补充资料”入口。

#### 未找到

- 行内容保持清晰，不使用大面积警告色。
- 我方产品显示`暂无直接匹配`。
- 行下方显示`查看公开平台候选`。

### 5. 行详情抽屉

点击某一行后，右侧面板内部展开详情，不覆盖整个页面。

详情分为四组：

1. 客户原始资料：来自哪个文件、哪一行或哪一张图片。
2. AI提取字段：名称、型号、规格、数量、场景。
3. 匹配依据：型号、名称、规格和产品库字段的对应关系。
4. 销售下一步：建议确认的问题和推荐跟进动作。

详情底部提供：

- `确认匹配`
- `标记待确认`
- `生成客户确认话术`

## 八、未匹配产品与公开平台候选

### 1. 触发方式

当产品库没有直接匹配时，右侧结果行出现一个轻量扩展入口：

`查看公开平台候选`

点击后，不离开当前页面，不新开复杂工作流。

### 2. 候选结果显示

候选区域使用右侧结果面板的下半区或抽屉展示，每条候选结果高度约 78px。

每条结果包含：

- 商品缩略图，建议 56 × 56px
- 商品标题，两行以内
- 来源平台：1688等公开平台
- 商品链接图标
- 相似特征：外观、名称或规格
- 状态：待人工核验

候选列表最多默认展示3条，更多结果通过“查看全部候选”进入。

### 3. 结果边界

候选区顶部固定显示：

`公开平台候选信息，仅供人工核验，不代表我方产品、价格或供货承诺。`

不能显示“同款已确认”“自动匹配成功”等表达。

## 九、底部固定操作区

### 视觉结构

底部操作区高度约 64px，使用半透明深蓝背景和顶部细分割线。操作区固定在页面内容底部，不随中间滚动内容消失。

左侧显示结果状态：

`3项已识别 · 2项已匹配 · 1项待确认`

右侧显示操作按钮。

### 按钮层级

#### 主按钮：一键导出Excel

- 科技蓝实心按钮
- 图标：下载或表格图标
- 点击后提示：`产品匹配结果已导出`
- 导出文件名包含客户名称和“演示数据”标识

#### 次按钮：一键发送客户

- 深色描边按钮
- 图标：发送图标
- 点击后打开发送预览，不直接发送

#### 辅助按钮

- `请求人工确认`
- `继续上传资料`
- `保存本次分析`

辅助按钮使用低权重文字按钮，不与主操作形成视觉竞争。

### 发送客户预览

发送预览使用右侧抽屉，不使用全屏弹窗。

预览内容：

- 客户名称
- 已识别产品数量
- 已找到匹配数量
- 待确认项目
- 给客户的说明文字
- 销售备注

底部按钮：

- `取消`
- `确认发送`

当存在待确认产品时，确认发送按钮旁显示：

`发送内容包含待确认项`

销售必须主动确认，系统不能自动发送。

## 十、动效规范

### 文件进入

- 文件项从接收区轻微淡入。
- 图标和状态点出现即可，不使用大幅飞入。

### AI分析

- 当前步骤颜色从灰蓝切换到冰蓝。
- 已完成步骤出现短促的状态确认。
- 当前字段以流式方式逐项出现，但每次只更新少量信息。

### 匹配结果

- 结果行按识别顺序轻微淡入。
- 高匹配结果先出现，待确认项随后出现。
- 未匹配项出现时，只使用一次低调提示，不持续闪烁。

### AI头像

- 固定位置，不跟随页面滚动漂移。
- 仅在分析中使用极弱的光晕变化。
- 分析完成后保持静态在线状态。

### 禁止动效

- 弹跳动画
- 连续大面积扫描线
- 结果表格整块翻转
- 多个卡片同时飞入
- 自动轮播公开平台商品

## 十一、页面状态稿

### 状态A：等待上传

- 左侧：大面积拖拽接收区
- 中间：六步流程全部未开始
- 右侧：空结果提示
- 底部：导出和发送按钮禁用

### 状态B：正在识别

- 左侧：文件列表显示识别状态
- 中间：第二步和第三步进行中
- 右侧：结果表显示骨架行或“等待匹配结果”
- 底部：仅保留继续上传和取消分析

### 状态C：部分匹配

- 左侧：全部文件已接收
- 中间：产品提取完成，存在规格差异提示
- 右侧：已找到、部分匹配和未找到混合显示
- 底部：导出可用，发送需要人工确认

### 状态D：匹配完成

- 中间：六步完成
- 右侧：匹配结果表完整可读
- AI建议给出下一步销售动作
- 导出Excel和发送客户入口激活

### 状态E：发现公开平台候选

- 中间：第五步高亮
- 右侧：未匹配行展开候选区域
- 公开平台提示固定显示
- 不改变企业产品库原有匹配结果

### 状态F：处理失败

- 中间明确失败步骤和原因
- 左侧对应文件出现失败状态
- 右侧保留已成功识别的结果
- 提供重新分析、替换文件、请求人工确认

## 十二、响应式适配

### 1440 × 900

三栏完整显示，底部操作区固定。产品匹配结果表展示全部字段。

### 1366 × 768

- 缩小顶部标题区和文件项间距。
- 中间AI建议最多显示两条。
- 右侧备注默认单行截断，点击展开。
- 底部操作区仍保持可见。

### 窄窗口

三栏按以下顺序纵向排列：

1. 客户资料
2. AI分析过程
3. 产品匹配结果

底部操作区保持固定，但按钮可以收敛为图标加文字。不能让结果表出现页面级横向滚动。

## 十三、设计验收标准

1. 页面第一眼能看懂“客户资料正在被AI处理”。
2. 左侧文件区域明确支持PDF、Word、Excel和图片。
3. 中间能看到可解释的AI工作步骤，不展示冗长内部思考文本。
4. AI建议与当前客户资料和匹配结果直接相关。
5. 右侧结果表至少包含客户产品名称、客户型号、我方对应产品、匹配度、是否找到、备注六列。
6. 产品库未找到时，可以看到公开平台候选的图片、标题、来源平台和链接。
7. 公开平台信息始终带有人工核验提示。
8. 底部可以直接找到导出Excel和发送客户。
9. 发送前必须预览并人工确认。
10. 页面整体保持深色、克制、企业级，不出现电商化和廉价科技风。
11. 不影响当前客户聊天、客户画像、快捷提问、转人工等既有能力。
12. 不出现未经确认的真实客户、真实平台数据、价格承诺或成交承诺。

## 十四、方案结论

这套UI的核心不是展示更多AI功能，而是把一次客户资料处理变成一条销售看得懂、客户愿意继续沟通的证据链：

> 文件进入系统，AI完成识别，产品得到匹配，差异被标记，销售确认后即可导出或发送。

页面高保真设计到此完成，等待产品经理评审确认后再进入交互原型和开发阶段。
