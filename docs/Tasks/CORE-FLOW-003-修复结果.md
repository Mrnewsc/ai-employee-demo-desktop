## 3. 当前上下文

`AppStore` 统一维护：

- `currentCustomerId`
- `currentQuoteId`
- `currentFollowupId`

选择客户或报价时会一次更新三项关联上下文。跨页跳转通过 `getSalesContextForCustomer(customerId)` 带入同一客户对应的报价和跟进任务，不依赖数组位置。

## 4. 客户线索状态联动

客户线索页从 `demoSales.customers` 动态读取状态，支持：

- 待联系
- 需求确认中
- 待报价
- 报价处理中
- 报价已发送
- 今日跟进
- 等待客户
- 需求确认完成

创建报价、发送报价、加入跟进和记录跟进结果后，线索卡片及详情中的当前状态同步更新。

## 5. AI 接待进入报价

AI智能接待按 `currentCustomerId` 加载对应客户的会话、画像、文件、提取字段和匹配结果。

资料分析完成后点击“生成报价草案”会：

1. 将当前报价更新为“待人工确认”。
2. 将客户更新为“报价处理中 / 报价”阶段。
3. 设置对应 `currentQuoteId`。
4. 跳转报价管理并自动打开该客户报价。

## 6. 报价进入跟进

报价管理使用共享报价状态：

`草稿 → 待人工确认 → 已确认待发送 → 已发送 → 待跟进`

- 人工确认后，报价状态同步为“已确认待发送”。
- 发送预览确认后，报价和客户状态同步为“已发送 / 报价已发送”。
- 加入跟进后，报价、跟进任务和客户同步为“待跟进 / 今日待跟进 / 今日跟进”，随后打开对应跟进任务。
- 未发送报价进入跟进时，不会生成“客户已收到报价”的状态，客户仍停留在报价处理阶段。

## 7. 跟进返回报价或接待

- “查看报价”通过当前 `customerId` 打开关联 `quoteId`。
- “进入AI智能接待”通过当前 `customerId` 返回对应客户会话。
- 跟进阶段条读取共享 `customer.salesStage`，可动态显示需求确认、报价或跟进。
- 记录“客户未回复”后，跟进任务和线索状态同步为“等待客户”。
- 记录“需要修改方案”后，客户回到“报价处理中”，关联报价回到“待人工确认”。

## 9. 仍然存在的限制

- 所有状态均为本地前端演示状态，不连接真实客户、平台或数据库。
- 沿用项目现有 LocalStorage 保存方式，不支持多设备、多用户或多窗口实时同步。
- 报价字段编辑和跟进表单内容仍是页面内演示输入；本轮共享的是核心销售状态和客户上下文。
- 时间线是统一的固定演示时间线，不会根据系统真实时间追加事件。
- 未接入 OCR、PDF真实解析、DeepSeek、OpenAI、1688、微信、邮件或其他真实接口。
